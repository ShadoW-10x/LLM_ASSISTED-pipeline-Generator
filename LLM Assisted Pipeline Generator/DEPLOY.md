# Deploying the Backend to AWS (Lambda + API Gateway)

- **Lambda** = runs your Python code only when called, no server to manage or pay for while idle
- **API Gateway** = gives Lambda a public HTTPS URL your CLI can call
- Both are free-tier eligible for this scale of usage

## Step 1 — Package the Lambda function

Lambda needs your code + dependencies zipped together.

```bash
cd aws_backend
pip install groq -t ./package
cp lambda_handler.py ./package/
cd package
zip -r ../lambda_deploy.zip .
cd ..
```

## Step 2 — Create the Lambda function (AWS Console)

1. Go to **AWS Lambda** → Create function
2. Choose "Author from scratch"
3. Name: `pipeline-generator`
4. Runtime: **Python 3.12**
5. Create function
6. Under "Code" → Upload from → `.zip file` → upload `lambda_deploy.zip`
7. Set **Handler** to: `lambda_handler.lambda_handler`

## Step 3 — Add your Groq API key as an environment variable

1. Go to Configuration → Environment variables
2. Add: `GROQ_API_KEY` = your key
   *(Later: for production you'd use AWS Secrets Manager instead of a
   plain env var — fine for a learning project for now.)*

## Step 4 — Increase timeout

LLM calls can take a few seconds. Default Lambda timeout (3s) is too short.

1. Configuration → General configuration → Edit
2. Set Timeout to **30 seconds**

## Step 5 — Create the API Gateway trigger

1. In your Lambda function page → Add trigger
2. Choose **API Gateway**
3. Create a new API → **HTTP API** (simpler/cheaper than REST API)
4. Security: **Open** (fine for a learning project; add an API key later if you want)
5. Add trigger

This gives you an **Invoke URL** like:
`https://abc123.execute-api.ap-south-1.amazonaws.com/default/pipeline-generator`

## Step 6 — Set the route to accept POST

By default API Gateway may only wire up the Lambda's default route.
In API Gateway console → your API → Routes → make sure there's a
`POST /generate` route pointing at your Lambda (or just use the
default route and matching URL in your CLI — either works, just keep
`API_URL` in `cli.py` consistent with whatever route you set up).

## Step 7 — Point the CLI at it

In `cli_app/cli.py`, set:

```python
API_URL = "https://YOUR-ACTUAL-INVOKE-URL"
```

## Step 8 — Test it

```bash
cd cli_app
pip install requests
python cli.py "Open-Meteo weather API, base url https://api.open-meteo.com, no auth, endpoint /v1/forecast, single JSON response with columnar hourly data (time, temperature_2m as parallel arrays), no pagination"
```

You should get `generated_pipeline.py` written locally, generated by
code that ran on AWS, not your machine.

## Common issues

- **"Internal server error"** → check CloudWatch Logs (Lambda console →
  Monitor → View logs) for the actual Python traceback
- **Timeout** → bump Lambda timeout further (Step 4)
- **CORS errors** (only relevant if you later build a real web frontend) →
  the handler already sets `Access-Control-Allow-Origin: *`

## Next steps once this works
- Add an API key requirement on API Gateway so randoms can't rack up your Groq usage
- Move `GROQ_API_KEY` into AWS Secrets Manager instead of a plain env var
- Add a `/health` route for a basic uptime check
- Put CloudWatch alarms on error rate — good AWS-fundamentals practice
